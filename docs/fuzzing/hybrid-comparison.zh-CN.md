# 转换器上：混合模糊测试与单独 AFL++ 的比较

在 `aba-convert` 的对账门上比较两种配置，同一台机器、各用同样的两颗核、同样的种子、同样的预算：

- **hybrid（混合）**——一个 AFL++ 主实例加 `symcc_fuzzing_helper` 作从实例，SymCC 在主实例的队列上求解分支条件，再把解出的输入交回来；
- **afl-pair（对照）**——一个 AFL++ 主实例加第二个 AFL++ 实例、不带 SymCC，让两种配置花同样的两颗核。

## 设置

- 镜像 `payslate-aba-symcc`：SymCC `3b8acabf06c8`（QSYM 后端）与 AFL++ `v5.02c`，都用 LLVM 15 构建；在 arm64 上原生构建、原生运行，不走模拟（和 KLEE 镜像不同）。
- 每种配置用 `--cpuset-cpus` 钉到两颗不相交的核（hybrid 用 0,1；afl-pair 用 2,3），同时运行，互不抢占 CPU。
- 种子 `fuzz/seeds/one-record.txt` 和 `fuzz/seeds/two-records.txt`（都对得上账），字典 `fuzz/aba.dict`。
- 每种配置跑 5 次、每次 10 分钟，AFL++ 随机种子分别为 1–5。
- 由 `symcc/summarise.py` 读取每次运行的 `plot_data` 和队列；原始运行不进仓库（用 `symcc/compare.sh 5 600` 复现）。

## 边覆盖随时间的变化

取主实例 `plot_data` 的 `edges_found`，五次运行的中位数与范围：

| 时间 | hybrid（中位数 [最小..最大]） | afl-pair（中位数 [最小..最大]） |
| ---: | --- | --- |
| 120 秒 | 106 [106..107] | 107 [105..107] |
| 300 秒 | 107 [107..107] | 107 [106..107] |
| 600 秒 | 107 [107..107] | 107 [107..107] |

两种配置都在头两三分钟内到达 107 条边并停住，边覆盖没有差别。对得上账的种子本来就把转换器一路带到了 `write_batch`，所以对账门之后的边从一开始就被覆盖了，用不同金额跨过这道门也不会多出边。

## 金额不同于种子、却仍对得上账的批次

把每个队列输入在普通构建下回放，统计那些被接受、且金额不在种子里的：

| | 第 1 次 | 第 2 次 | 第 3 次 | 第 4 次 | 第 5 次 |
| --- | ---: | ---: | ---: | ---: | ---: |
| hybrid | 0 | 0 | 0 | 0 | 0 |
| afl-pair | 0 | 0 | 0 | 0 | 0 |

十分钟里，两种配置都没有产出金额不同的新对账批次。要把门往*新*金额的方向解开，helper 需要一个过不了门的队列条目（一个金额被改过的批次）；这次比较没有记录 helper 拿到了哪些输入。

## 怎么读这组数

在这个转换器上、这个预算下，把 SymCC 放在 AFL++ 旁边一起跑，相比单独 AFL++ 没有换来任何东西：边覆盖一样，也没有新的对账批次。当 SymCC 被直接对准一个金额被改过的批次时，它确实能跨过对账门——`symcc/run-symcc.sh symcc/seeds/mismatch.txt` 就解出一个，那个解出的批次被留作回归和种子——但作为模糊器旁边的一个连续回路，它在这里不划算。ADR 0017 记录了这把混合模糊测试带到了什么位置。
