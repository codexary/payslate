# ADR 0008：拒绝工资批次事件时保持批次不变

Ravi Menon — 2026-05-22

## 状态

2026-05-22 采纳。

## 背景

`PayRun` 从 `DRAFT` 开始，依次接受 `CALCULATE`、`APPROVE`、`PAY` 和 `REVERSE`。最初的实现允许在 `APPROVED` 状态再次执行 `APPROVE`：它增加 `approvalCount`，却不改变状态，随后正常返回。`PayRunStateTest` 暴露了这条路径。修复后的实现通过迁移表拒绝该事件，且在拒绝前不修改任一字段。重复付款授权是业务风险；对象本身并不发送付款。

实发工资测试也说明了测试边界的重要性。始终返回零的 `Withholding` mock 无法区分原始总工资与调整后的总工资。换用真实的示例税表后，$650.00 周薪加上 −$200.00 更正，暴露出应付 $450.00、实际却付 $435.00 的问题。现在，`NetPay` 仅在调整后总工资为正时按该金额计税，否则跳过计税。税表入口本身拒绝负总工资。状态与实发工资用例见 [docs/test-design/payrun-states.md](../test-design/payrun-states.zh-CN.md)。

## 决定

在 [docs/test-design/payrun-states.md](../test-design/payrun-states.zh-CN.md) 保留明确的迁移表。测试四条允许的迁移，以及 16 个被拒绝的状态／事件组合。每次拒绝都检查异常，并检查 `state` 和 `approvalCount` 未变。状态测试使用真实 `PayRun`，通过公开操作将它带到各个起始状态。无效事件必须在修改状态或批准次数之前失败。

`EmployeePay` 的子类型另用共享合约测试；每个具体类型的测试类都必须继承这些测试，并提供真实实现。使用 `Withholding` 替身检查固定响应下的金额运算，同时保留使用真实税表的 `NetPayScheduleTest`，检查计税依据及更正对实发金额的影响。仅凭恒定返回值不能证明计税输入正确。

## 考虑过的方案

- **只测试成功路径：**无法覆盖重复批准或过早 `PAY`。
- **在状态测试中 mock `PayRun`：**mock 只按设置回答，不会暴露真实对象的 `approvalCount` 变化。
- **用生成的历史替换产品测试：**这让一条很小的业务规则更难审查，仍需另外检查被拒绝事件的副作用。
- **只用返回零的计税 mock：**错误和修复后的计税输入都能通过同一组实发金额断言，真实税表用例才能将两者区分开。

## 后果

增加状态或事件时，须同时更新表和测试。拒绝契约同时保护可见状态和批准次数；只检查异常或只检查状态都不够。当前对象只保存在内存里；持久化和并发批准保护留给使用它的服务。

员工共享测试只能确认已测试输入下的共同行为，不能证明各子类型的具体工资公式正确。真实税表的实发工资测试与固定响应测试互为补充；合成的示例税表不能证明计算符合官方税表。
