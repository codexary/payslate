# ADR 0003：工时表导入格式契约

## 状态

2026-03-20 采纳。

## 背景

团队于 2026-03-16 至 2026-03-19 通过[工时表格式原型](https://github.com/codexary/payslate-spike-timesheet-formats)，在产品导入器实现前梳理格式选择。`TimesheetImporterTest` 包含 22 个测试案例：12 个支持类代表、10 个拒绝类代表。[原型结论](https://github.com/codexary/payslate-spike-timesheet-formats/blob/main/FINDINGS.zh-CN.md)区分了这些测试实际检查的行为与更完整的目标契约。合成文本不能验证真实厂商导出文件、流式处理或产品 API。

## 决定

产品导入器采用以下契约：

| 维度 | 支持范围 |
| --- | --- |
| 分隔符 | 逗号、分号或制表符，由表头确定，整个文件保持一致 |
| 必需表头 | `employee` / `employee name` / `staff`；`date` / `shift date`；`start` / `start time`；`end` / `end time`，不区分大小写 |
| 日期与时间 | ISO `yyyy-MM-dd` 或澳大利亚 `d/M/yyyy` 日期，并校验日历有效性；24 小时 `HH:mm` 或 12 小时 `h:mm AM/PM` 时间 |
| 公共假日 | 可选列 `public holiday` / `public_holiday` / `holiday`；不区分大小写的 `true` / `yes` / `1` 和 `false` / `no` / `0` / 空值；缺列视为 false |
| 文本与行 | 文件开头可选 UTF-8 BOM；引号内分隔符及双引号转义；忽略空行；接受 LF 和 CRLF |
| 班次关系 | 一个日期加起止时间；结束时间早于开始时间表示次日；起止相同按零时长拒绝 |

混用分隔符、未知或缺失表头、非法日期时间、数据内 BOM、未闭合引号、列数错误、空员工姓名、单独 CR、零时长和非法公共假日值都应返回明确错误。公共假日列是独立的 Boolean 分区：true 与 false 都必须正确保留，缺列默认 false。

这种格式无法表达 24 小时或更长的班次。起止时间不同时，所得时长小于 24 小时；相同时表示零时长，而不是一整天。要支持更长班次，须改变格式，例如增加结束日期；“超过 24 小时”不是原型中可到达的拒绝类别。

产品导入器使用维护中的 CSV 解析器，并流式读取。原型先按行切分输入，对引号内换行返回 `Unclosed quoted field`。产品导入器必须在发布前明确决定是否支持引号内换行，并为该决定编写测试。

原型解析器不是产品解析器。它会查找必需表头的别名，却不会拒绝所有额外的未知列，也没有通用的数据内 BOM 检查。上述产品校验要求仍需实现并测试。

## 考虑过的方案

- 只接受逗号、ISO 日期和 24 小时时间。这会排除原型支持案例已经表示的格式类别。
- 直接把原型解析器复制到产品。它的按行切分和小型引号解析器不提供所需的流式处理与校验契约。
- 把起止时间相同解释为 24 小时班次。这会悄悄改变原本拒绝零时长的含义，仍无法表达更长班次。

## 后果

产品测试必须在导入边界覆盖支持和拒绝的类别，包括解析后的公共假日标志，以及选定的引号内换行行为。原型的 22 个测试只确定格式决策，不能证明产品导入器或真实厂商导出文件可用。超出这些代表案例的解析行为仍须对照契约检查，不能假定原型已经完成全面的 CSV 校验。
