# ADR 0007：先审查存活变异体，再决定分数门槛

Ravi Menon — 2026-05-08

## 状态

2026-05-08 采纳。

## 背景

YTD 的半分错误把要求的 `HALF_EVEN` 写成了 `HALF_UP`。只断言结果非负的测试仍通过。精确金额断言暴露了错误；精确的 `roundedCents` 断言则能拒绝非负断言所接受的返回零变异体。

当前完整 `pay-engine` 分析生成 61 个变异体：杀死 49 个、存活 8 个、未覆盖 4 个。原始分数为 49/61 = 80.33%（PIT 显示 80%）。行覆盖为 81/98（显示 83%），test strength 为 49/57（显示 86%）。报告 [docs/quality/mutation-report.md](../quality/mutation-report.zh-CN.md) 列出了当前代码位置和结果。其中两个存活项在说明 [docs/test-design/equivalent-mutants.md](../test-design/equivalent-mutants.zh-CN.md) 中有注明输入域的等价证明；只扣除这两项，得到 49/59 = 83.05%。另六项尚未分类。

已有的 JaCoCo 65% bundle 分支门槛规定了覆盖率底线，但不能说明断言能否拒绝错误金额。变异审查要回答的是后一个问题。

## 决定

Olivia Brooks 与 Hannah Schmidt 逐项核对存活变异体的业务规则和测试断言。新增测试须有独立于变异体的预期值，并先在原程序上通过。若判定等价，记录代码位置、变异算子、输入域和理由。未分类与未覆盖的变异体仍计入分母。

Pull request 的 `mutation-changed` job 从基线到 `HEAD` 的差异中选出改动过的 `pay-engine` 生产 Java 文件路径，对每个对应的类名模式分别调用 PIT，范围包含嵌套类。没有匹配的源码改动时，不调用 PIT。夜间任务每天 03:15 UTC 分析完整模块，也支持手动触发。这两个范围分别由 `.github/workflows/ci.yml` 和 `.github/workflows/mutation-nightly.yml` 定义。

团队同时报告原始分数、杀死／存活／未覆盖数量，以及有单独论证的调整后分数。目前不为这条基线设置数值门槛。分数提醒团队审查，不能证明薪资计算正确。

## 考虑过的方案

- **立即设置数值型变异门槛：**单一门槛会把已证明等价项、未分类存活项和未覆盖代码混为一谈，无法解释各项含义。先审查这些类别，再选择可维护的门槛。
- **只依赖分支覆盖：**执行覆盖不能说明断言是否能区分错误金额与预期金额。
- **只分析改动类：**这会遗漏未改动类中的变异，而且只修改测试不会让该 job 调用 PIT。因此保留夜间完整模块分析。

## 后果

按改动类运行能提供有针对性的反馈，但不能评价所选范围之外的变异。完整运行会消耗更多测试执行和机器时间；当前分析检查了 11 个测试，对 61 个变异体记录了 362 次测试执行。这些是 PIT 的分析计数，并非完整 JUnit 测试套件的测试数。两条流程的结果都需要人审查。

第 97 行的预扣税等价证明依赖随代码提供的合成示例税表，税表变化时必须重查。第 85 行的加班倍率证明依赖实际调用的输入域及可观察的返回值。另六项未分类存活体和四项未覆盖体是明确的后续工作；CI 通过或调整后的分数都不能代替对这些项的处理。
