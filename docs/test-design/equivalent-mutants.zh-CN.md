# 等价变异体

Olivia Brooks — 2026-05-08

`SURVIVED` 仅表示现有测试未检出，不能直接判为等价。使用 PIT 1.30.1 和 `pitest-junit5-plugin` 1.2.3 的完整 `pay-engine` 分析有八个存活项，其中只有下面两项已有等价证明。两项均为 `pay-engine/src/main/java/com/elsworne/payslate/engine/LegacyPayEngine.java` 中的 `ConditionalsBoundaryMutator` 变异。

## 加班倍率：第 85 行

`overtimeFactor` 中的 `factor < tier` 被改为 `factor <= tier`。两种判断只在 `factor == tier` 时不同。原程序保留 `factor`，变异体则把与它相等的 `tier` 赋给它。不相等时，两版执行同一分支，返回值也相同。

证明的输入域限定为 `calculate` 对该方法的实际调用：倍率为有限正数 `1.0`、`1.25`、`1.5`、`2.25`，加班档位为 `1.5` 或 `2.0`。可观察结果是返回的倍率及据此计算的工资。相等时，两者是同一个正 `double` 值，赋值不会改变倍率或工资。这个证明不需要对调用范围外的任意浮点输入作假设。如果调用的输入域或方法的可观察行为发生变化，须重新检查。

## 预扣税：第 97 行

`withholding` 中的 `gross.compareTo(candidate) >= 0` 被改为 `> 0`。当税前金额为非空 `BigDecimal`，且使用随代码提供的 `example-tax-schedule.csv` 时，两版只可能在金额恰好等于某档下限时选中不同的行。该表的下限为 `0.00`、`500.00`、`1000.00`，对应的税额基数／超出部分税率分别为 `0.00/0.00`、`0.00/0.10`、`50.00/0.20`。

返回金额的计算式为 `base + (gross - min) * rate`，最后用 `HALF_UP` 保留两位小数。

| 恰好达到下限的税前金额 | 原程序：相等时选中该档 | 变异体：保留前一档或初始值 | 两版返回的金额 |
| ---: | --- | --- | ---: |
| 0.00 | `0 + (0 - 0) * 0` | 初始 `min`、`base`、`rate` 均为零 | 0.00 |
| 500.00 | `0 + (500 - 500) * 0.10` | `0 + (500 - 0) * 0` | 0.00 |
| 1000.00 | `50 + (1000 - 1000) * 0.20` | `0 + (1000 - 500) * 0.10` | 50.00 |

其余金额下，两版的判断选中相同的行；金额小于零时，两版均保留初始零值。在每个下限处，两个公式在舍入前已经相等，最终返回的两位小数金额也相同。改动的条件不影响资源处理或 CSV 解析。这个证明只适用于随代码提供的合成示例税表；该表不是官方税表。税表发生变化时须重新核对，不能把结论推广到任意生产税表。

## 仍需审查的项

其余六项存活变异体尚未分类：`calculate` 第 17、36（两项）、38 行的四个条件边界，第 24 行删除 `Collections.sort` 的变异，以及第 25 行匿名比较器返回零的变异。这些项需要有针对性的测试或进一步分析。此外，`PayCli.main` 有四个 `NO_COVERAGE` 项，位于 `PayCli.java` 第 17、23（两项）、25 行，均未判定为等价。[变异测试报告](../quality/mutation-report.zh-CN.md) 列出了全部八个存活项及分析统计。

## 精确分值断言的作用

对新建累计器加上 `0.005` 时，`roundedTotalIsNotNegative` 无法区分错误的 half-up 结果 `0.01` 与规则要求的 half-even 结果 `0.00`；它对分值的断言也接受零。`roundsHalfCentToEvenAndReportsExactCents` 首先要求 `0.00`，从而暴露原先的 `HALF_UP` 错误。修复为 `HALF_EVEN` 后，它向同一个累计器再加 `12.34`，要求金额为 `12.34`，并检查分值恰好为 `1234`。在当前分析中，这个测试杀死了 `YtdAccumulator.java` 第 12 行的 `PrimitiveReturnsMutator` 变异，即让 `roundedCents` 返回零。同理，只断言非空可以拒绝 null，却仍会接受非空的错误金额。

原始分数为 49/61 = 80.33%；仅扣除两个已证明等价项后为 49/59 = 83.05%。六个未分类存活项和四个未覆盖项仍计入调整分数的分母。这些分数说明断言对所选变异的辨别能力，不能证明薪资计算正确。
