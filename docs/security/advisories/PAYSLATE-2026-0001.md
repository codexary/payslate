# PAYSLATE-2026-0001: Memory-safety defects in the aba-convert converter

- Status: fixed
- Published: 2026-08-27
- Component: `legacy/aba-convert` — the inherited local desktop converter that prepares
  bank files from a desktop export
- Affected: `aba-convert` builds before the fixes below (before the 1.0.0 release)
- Fixed in: 1.0.0 (commits `bdd95d6` and `4b12656`)

## Summary

`aba-convert` is a local command-line tool. An operator runs it on a desktop export
file to produce an ABA bank file. Two defects let a crafted or corrupted export file
corrupt memory or the written total when the operator converts it. The hosted Payslate
service does not run this tool; its ABA export is a separate code path and is not
affected.

## Finding 1 — account-name stack buffer overflow

The converter copied the 40-character source account-name field into a 24-byte stack
buffer with `strcpy`, so a name longer than 23 characters overflowed the buffer. A
crafted export with a long account name could corrupt the stack and, in the worst case,
lead to code execution in the operator's session.

- Weakness: CWE-121 stack-based buffer overflow (CWE-787 out-of-bounds write)
- CVSS 3.1: `AV:L/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H` — base score 7.8 (High)
- Fix: `bdd95d6` — copy the name into the output field with a bounded `snprintf`
- Regression: `legacy/aba-convert/tests/run-sanitizers.sh` replays
  `fuzz/crashes/name-overflow.txt` under AddressSanitizer (`da82df6`)

## Finding 2 — batch-total integer overflow

The converter accumulated the batch total in a 32-bit `int` and parsed each amount with
`atoi`, which neither validates the field nor bounds the result. A file whose amounts
sum past the 32-bit range overflowed the total (undefined behaviour), so the written
control total did not match the detail records.

- Weakness: CWE-190 integer overflow
- CVSS 3.1: `AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:H/A:N` — base score 5.5 (Medium)
- Fix: `4b12656` — reject a non-digit or empty amount, parse in 64 bits, and keep each
  amount and the running total within the ten-digit output fields
- Regression: `legacy/aba-convert/tests/run-sanitizers.sh` replays
  `fuzz/crashes/total-overflow.txt` under the sanitizer build (`10232cb`)

## Impact boundary

Both defects are in the local converter only. Exploitation requires an operator to run
`aba-convert` on a crafted export file on their own machine; there is no remote vector.
The hosted API builds ABA files through a different, unaffected path.

## Remediation

Rebuild `aba-convert` from the 1.0.0 release. No configuration change is needed. Sites
that cannot rebuild immediately should treat desktop export files as untrusted input
and convert only files from a known source.

## Scores

The CVSS 3.1 base scores above were computed from the vectors by the standard formula
and cross-checked with the pinned `cvss` 3.4 reference implementation; both give 7.8 and
5.5. The score is advisory; each site should reassess for its own environment.
