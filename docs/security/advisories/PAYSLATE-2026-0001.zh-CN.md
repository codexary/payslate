# PAYSLATE-2026-0001：aba-convert 转换器的内存安全缺陷

- 状态：已修复
- 发布：2026-08-27
- 组件：`legacy/aba-convert`——继承来的本地桌面转换器，从桌面导出准备银行文件
- 受影响：下列修复之前的 `aba-convert` 构建（1.0.0 发布之前）
- 修复于：1.0.0（提交 `bdd95d6` 与 `4b12656`）

## 概述

`aba-convert` 是一个本地命令行工具。操作员在桌面上对一份导出文件运行它，产出 ABA 银行文件。两处缺陷使得一份构造或损坏的导出文件在转换时能破坏内存或写出的合计。托管的 Payslate 服务并不运行这个工具；它的 ABA 导出是另一条代码路径，不受影响。

## 发现 1 —— 账户名栈缓冲区溢出

转换器用 `strcpy` 把 40 字符的源账户名字段拷进一个 24 字节的栈缓冲区，于是超过 23 字符的名字就溢出了缓冲区。一份带长账户名的构造导出可以破坏栈，最坏情况下在操作员的会话里导致代码执行。

- 弱点：CWE-121 栈缓冲区溢出（CWE-787 越界写）
- CVSS 3.1：`AV:L/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H`——基础分 7.8（高）
- 修复：`bdd95d6`——用有界的 `snprintf` 把名字拷进输出字段
- 回归：`legacy/aba-convert/tests/run-sanitizers.sh` 在 AddressSanitizer 下重放 `fuzz/crashes/name-overflow.txt`（`da82df6`）

## 发现 2 —— 批次合计整数溢出

转换器把批次合计累加在一个 32 位 `int` 里，用 `atoi` 解析每笔金额——既不校验字段，也不限制结果。一份金额之和越过 32 位范围的文件会让合计溢出（未定义行为），于是写出的控制合计和明细记录对不上。

- 弱点：CWE-190 整数溢出
- CVSS 3.1：`AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:H/A:N`——基础分 5.5（中）
- 修复：`4b12656`——拒绝非数字或空的金额字段，用 64 位解析，并把每笔金额和累计合计都限制在十位输出字段内
- 回归：`legacy/aba-convert/tests/run-sanitizers.sh` 在 sanitizer 构建下重放 `fuzz/crashes/total-overflow.txt`（`10232cb`）

## 影响边界

两处缺陷都只在本地转换器里。利用它需要操作员在自己机器上对一份构造的导出文件运行 `aba-convert`；没有远程途径。托管 API 通过另一条不受影响的路径产出 ABA 文件。

## 处置

从 1.0.0 发布版重新构建 `aba-convert`。无需改配置。无法立即重建的站点应把桌面导出文件当作不可信输入，只转换来源已知的文件。

## 分数

上面的 CVSS 3.1 基础分由标准公式从向量算出，并用钉住版本的 `cvss` 3.4 参考实现交叉核对；两者都给出 7.8 和 5.5。分数仅供参考，各站点应按自己的环境重新评估。
